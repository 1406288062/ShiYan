# 在用户的机器上安全修改

## 写入和删除先问
- 写数据库、向量库，或改动用户没要求改的文件之前，先用 needs_approval 或 blocked 问用户。
- 删除代码、数据或文件之前先问，即使看起来只是顺手清理。
- 补数据或改写已有记录之前先问，并写明要改哪些记录、改成什么值。
- 提问时也说明不会改什么，让一次同意只覆盖一个明确的动作。

## 只改被要求的
- 动手前重读用户的要求，列出它点名的文件和服务，只改这些。
- 相关的改进需要动别的文件或服务时，停下来单独提出，不要顺手并进来。
- 临时绕过的办法要标明是临时办法，不要说成根本修复。

## 只重启点名的服务
- 用 systemctl 重启，执行前写明要重启哪一个服务。
- 不用按名字或模式匹配的批量 kill；不重启用户没点名的服务。

## 重启后逐个核对
- 先确认被重启的服务是 active 并在监听应有的端口。
- 再检查相关服务（网页、运行时、模型中枢等）是否仍然正常，按服务名逐个汇报。
- 某个相关服务因此停了，停下来告诉用户停了什么、为什么，不要连续重启去“救”。
- 有风险的修改先给回滚方案：要恢复的提交或备份是哪个。
