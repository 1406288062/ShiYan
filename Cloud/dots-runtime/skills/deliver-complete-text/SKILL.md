# 完整交付长文本

## 先确认要什么
- “全文”指一个完整文件，不是链接列表或节选；除非用户只要链接。
- 先确定版本、语言、应有的章节数、第一章和最后一章的标题，再去取内容。
- 用户一次要多部作品时，每部单独一张检查清单，各自过关才算完成。

## 优先单个可靠来源
- 优先找已经整理好的单文件版本（例如维基文库整本、Project Gutenberg）；逐章抓网页更容易被限流、留下缺口。
- 拿到后数章节标题、看第一章、看最后一章、确认结尾没有被截断。
- 记下用的版本，以及和用户要求的版本有什么不同。

## 有缺口时
- 缺章时，把不完整的文件单独保存并在文件名和说明里标“不完整”。
- 在交付说明里按编号列出缺失章节，并说明下一步打算怎么补。
- 某个来源开始限流就停，换整本来源或稍后重试；绝不用编写或改写的文字填补缺口。
- 合并两个来源后，重新核对章节数、首章、末章，并在说明里写明混用了哪些版本。

## 核对后交付
- 章节数、首章、末章、结尾全部通过，才能说“完整”。
- 说明版本、章节数，以及保留下来的原始来源错误（例如乱码），不要悄悄改掉。
- 还有作品没完成时说清楚哪部没完成；每部核对通过就先交付那一部。
