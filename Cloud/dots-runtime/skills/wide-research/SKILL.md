# 批量调研

## 适用
- 任务能拆成许多互不依赖的小项（每个对象一项），每项要产出同样的字段。
- 单个对象的调研、或者各项互相依赖时不要用。

## 开始前
1. 把输入列表去重、规范化（统一名称、去掉空项），写进任务目录里的 `items.json`。
2. 定一个最小、明确的输出字段表（字段名 + 类型），不要自由文本字段，除非用户要。
3. 先完整做完第 1 项，确认字段都填得出来、耗时和资源可接受，再批量做其余项。

## 执行
- 每项单独记录到 `results.jsonl`（一行一个对象，带稳定的 key），做完一项写一项；中途被打断，下次唤醒只补没完成的项，已完成的不重做。
- 能写脚本批量处理的（抓取、解析、格式化）就写脚本跑，并抽查几项结果。
- 某项失败：先查原因再重试那一项，不要整批重来；仍然失败就记进 `failures`，写明原因。
- 量大时用 finish_run 的 continue 分几轮做，每轮在 summary 里写进度（已完成 N/总数）。

## 交付
- 最终结果整理成用户要的格式（表格、Word、Excel 等），并核对行数和字段。
- 报告“已核实覆盖率 = 成功数/总数”，分别列出：失败的、未开始的、被跳过的，以及原因。
- 一项即使重试多次，也只算一次。
